# 日常维护：什么时候写、写什么、写多大

本文件给 agent 读。目标：让 `notes/` 里每一篇都能在三个月后被 `mem find` 找到、被一句 description 说清、读完就能用。

## 1. 什么时候写

当场写，不攒到最后。触发条件（满足任一）：

- 做出一个**能被复用**的结果：一个可用脚本、一条跑通的命令序列、一个配置配方。
- 解决一个**会再出现**的问题：报错的真实原因、绕过方法、诊断步骤。
- 被用户**纠正**一次：用户说「不是这样」「我说过」「别再」。写成 `--type feedback`。
- 做出一个**决策**并有理由：选 A 不选 B、某功能不做。
- 发现一个**事实**以后要查：端口、路径约定、版本差异、外部 API 的怪癖。写成 `--type reference`。

不写：

- 一次性的过程日志、闲聊、已经在代码注释或 README 里写清楚的东西。
- 未验证的猜测。要写就标明「未验证」，并写清验证方法。
- secret、token、密码、私钥、邮箱、个人身份信息。需要时只写「在哪里取」，不写值。

## 2. type 怎么选

| type | 内容 | 例 |
|---|---|---|
| `project` | 本项目做了什么、现在是什么状态 | 「部署分两步：release 不等于上线」 |
| `feedback` | 用户的纠正与偏好，以后必须遵守 | 「交结果，不交建议清单」 |
| `reference` | 查表型事实 | 「CLI 2.0 把 --out 改名 --output」 |

## 3. 写什么：一篇 note 的形状

```bash
mem add <slug> --type <type> [--pack <id>] [--title "标题"]
```

- **slug**：英文小写加连字符，名词短语，能被 grep 到。日期自动加前缀。例：`release-vs-restart`。
- **title（H1）**：具体，带关键名词。不要写「一些发现」「今天的问题」。
- **description**：一句话，回答「这是什么 + 什么时候要用」。它会原样出现在 catalog、pack、热档里，是检索命中的主要依据。把最可能被搜的词放进去。
- **FACT**：现场证据。命令、输出、文件路径、版本号、日期。别人能据此复现。
- **决策／结论**：一两行。
- **坑**：下次怎么避开。这是最值钱的一节。
- **相关**：`[[其他 note 名]]`，名字用 `mem find` 取，不凭印象写。

## 4. 粒度

- 一篇 note 一个主题。能用一句 description 说清就是对的粒度；说不清就拆。
- 典型大小 1-4 KB。超过 8 KB 通常是把过程日志也塞进来了，删掉过程，留结论和证据。
- 同一主题的后续进展：**改原文**并更新 description，而不是新建「xxx-续」「xxx-v2」。

## 5. 去重

写之前先查：

```bash
mem find <主题关键词>
mem find <另一个说法>
```

- 命中且是同一件事 → 编辑那一篇，补 FACT，更新 description。
- 命中但结论相反 → 编辑旧篇，在结论里写「YYYY-MM-DD 起改为……，原因……」，旧结论保留为删除线或「历史」段。
- `mem build` 输出的 `duplicate_content` > 0 表示有内容完全相同的文件，找出来合并。

## 6. 过期

记忆会过期。发现一篇 note 与现场不符时：

1. 以现场为准完成当前任务。
2. 打开那篇 note，在顶部结论处写明「YYYY-MM-DD 已失效：……」，并把 description 改成以「（已失效）」开头。
3. 不删除文件。删除只在用户明确要求时做。

## 7. build

每次新增或编辑 note 之后：

```bash
mem build
```

看输出：

- `no_description` > 0：有 note 没填 description，`mem find` 时只能靠正文首段兜底。补上。
- `unclassified`：落到 `misc` 的数量。持续增长说明 `packs.json` 的关键词需要更新，或该新开一个 pack（见 `proactive-build.md`）。
- `WARN MEMORY.md ... 超预算`：Tier-0 太大，见 `proactive-build.md` 的「修剪 Tier-0」。
- `WARN pack 超预算`：某个 pack 太大，考虑拆分。

定期（或怀疑有问题时）跑 `mem doctor`，`VERDICT: OK` 为合格。
